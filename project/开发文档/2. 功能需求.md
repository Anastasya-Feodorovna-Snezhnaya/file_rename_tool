# 2. 功能需求

## 2.1 普通批量重命名

- 用户选择一个目录，操作不递归进入子目录。
- 扩展名筛选默认值为 `.png`；输入 `*` 时包含所有普通文件。
- 文件排序以去掉最后一个扩展名后的文件名为主键；主键相同时按扩展名和完整文件名排序，确保结果稳定。
- 用户设置新前缀、尾部格式和起始序号。
- 尾部格式必须且仅包含一个小写 `n`；生成时用零填充后的序号替换它。
- 每个输出文件保留对应源文件的扩展名，包括扩展名大小写。
- 点击执行时必须重新扫描目录，不得仅依赖上一次刷新缓存的列表。

## 2.2 文件序列插入

- 两组文件位于同一目录。
- 文件名匹配形式为：`前缀 + 尾部格式（n 对应十进制数字）+ 可选扩展名`。
- 两组序列分别按数字序号升序排列；同序号时按扩展名和完整文件名稳定排序。
- 插入位置输入 N，表示插入到第一组第 N 个文件之后；0 表示插入到第一组之前。
- 合并顺序为：第一组前 N 个文件、第二组全部文件、第一组剩余文件。
- 合并后按顺序从起始序号开始重新编号，所有文件使用同一新前缀和尾部格式。
- 每个文件保留自己的原始扩展名。
- 两组匹配结果为空、两组发生重叠、插入位置越界或目标文件名冲突时，拒绝执行并说明原因。

## 2.3 编号位数

基础位数为表示总文件数所需的最少十进制位数，即 `len(str(total_count))`。

### 固定增加位数

最终位数 = 基础位数 + 额外位数；额外位数范围为 0～5，默认 0。

### 按容量阈值自动增加位数

令基础位数为 d，容量为 `10 ** d`，比例为 `total_count / capacity`。当比例严格大于阈值百分比时，最终位数为 d + 1，否则为 d。阈值范围为 0～100%。

两种模式互斥，配置持久化到当前工作目录的 `settings.json`。

## 2.4 安全和异常

- 预览确认前完成输入校验、源文件存在性检查和目标路径冲突检查。
- 目标文件名不能重复；若目标文件已存在且不属于本次操作的源文件集合，则拒绝执行。
- 执行时采用“源文件 -> 唯一临时文件 -> 最终文件”的两阶段重命名。
- 中途失败时尽可能回滚已完成步骤，并在错误提示中说明回滚结果。
- 日志记录扫描、计划、执行结果和异常；避免只在控制台输出错误。
